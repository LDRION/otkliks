# E2E-тесты (Playwright)

Проверяют marketing-site как BFF поверх `core-api` — значит перед запуском должны
работать оба сервиса плюс MongoDB.

## Перед запуском

1. MongoDB запущен (`mongodb://127.0.0.1:27017` по умолчанию).
2. `core-api` запущен и слушает `:4000` (`cd apps/core-api && pnpm start`), с заполненным
   `.env` (как минимум `AUTH_SECRET`, `MONGODB_URI`).
3. `marketing-site`'s `.env.local` содержит **тот же** `AUTH_SECRET`, что и `core-api` —
   иначе middleware не сможет проверить клиентские сессии.

Сам marketing-site поднимать не нужно — `playwright.config.ts` сделает это сам
(`reuseExistingServer: true`, так что если dev-сервер уже запущен, тесты просто
переиспользуют его).

## Запуск

```
pnpm --filter @hhpilot/marketing-site test:e2e
```

## Что покрыто

- `customer-flow.spec.ts` — регистрация (с авто-триалом), выход, повторный вход, неверный пароль
- `trial.spec.ts` — 24ч триал выдаётся автоматически без кнопки; повторное использование
  того же резюме hh.ru на втором аккаунте отзывает у него триал
- `profile.spec.ts` — несколько резюме одновременно: добавить, сохранить, пережить reload, удалить
- `devices.spec.ts` — пейринг устройства (как это делает local-agent) → видно в кабинете → отвязать
- `payment.spec.ts` — оплата: реальная ссылка на ЮMoney, если кошелёк настроен, иначе честная
  ошибка (форсирует "триал закончился" напрямую в MongoDB — свежий триал маскировал бы
  карточку оплаты)
- `admin.spec.ts` — вход в админку, ролевой гейт `/admin/users`, редирект анонимных
- `public-pages.spec.ts` — смоук по публичным страницам без ошибок в консоли
- `counselling.spec.ts` — автозаполнение формы для залогиненных клиентов

## Чего тут нет и почему

Реальный отклик на hh.ru, окно `local-agent` (Electron) и живой вызов Siberi API — вне
охвата этого набора: первому нужен настоящий аккаунт hh.ru, второму — GUI-окружение,
третьему — сетевой доступ к внешнему API с реальным ключом. Всё это тестируется руками.
